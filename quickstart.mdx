<Steps>
  <Step title="Clone the repository">
    ```bash
    git clone https://github.com/R0N7w7/DailyFocus_LocalFirst.git && cd DailyFocus_LocalFirst
    ```
  </Step>

  <Step title="Install dependencies">
    Requires **Node.js 18+** and **npm**.

    ```bash
    npm install
    ```
  </Step>

  <Step title="Start the dev server">
    ```bash
    npm run dev
    ```

    Vite starts the app at [http://localhost:5173](http://localhost:5173). The `--host` flag is included in the script, so the server also binds to `0.0.0.0` — making it reachable from other devices on your local network.
  </Step>

  <Step title="Open the app">
    Navigate to [http://localhost:5173](http://localhost:5173) in your browser. The app loads immediately with no login screen.
  </Step>

  <Step title="Add your first task">
    On the main screen you will see a task input form:

    1. Enter a title in the **title** field (required).
    2. Optionally fill in the **description** field for more detail.
    3. Click **Añadir tarea** to save the task.

    The task appears immediately in the list below the form.
  </Step>
</Steps>

<Note>
  All data is stored locally in your browser's IndexedDB — no account or sign-up required.
</Note>

## What happens under the hood

When the app boots, `main.tsx` renders a `<QueryClientProvider>` that wraps the entire component tree, providing a shared TanStack Query cache to every component in the app.

When you click **Añadir tarea**, the form calls the `useAddTask()` hook. That hook runs a mutation that calls `taskService.addTask()`, which writes the new `Task` record to the local [Dexie](https://dexie.org/) database — a thin wrapper around the browser's **IndexedDB**. Once the write succeeds, the mutation invalidates the `['tasks']` query key, causing TanStack Query to re-fetch the task list and re-render the UI with the updated data.

No network request is made at any point. Every read and write goes through Dexie → IndexedDB, staying entirely on-device.
